# 00 固定内容与核对基准

本培训的所有输入都由确定性公式或固定文档生成。只要从空状态起步（`run_all.sh` 会自动清空
`evidence/run/`），下表的值在任何机器、任何次数的复跑中都保持不变。时间戳字段会变，
文末单独列出"哪些会变、哪些不会变"。

## 1. 源素材（`training/assets/`）

| 文件 | 尺寸 | 编码 | 字节数 | sha256 |
|---|---|---|---|---|
| `asset-a.png` | 16x16 | 8-bit RGBA | 126 | `fce5d44a93777695889c03941c61d7517cce82a1dc766bb2734bd2b353fe3c2d` |
| `asset-b.png` | 16x16 | 8-bit RGBA | 156 | `798c47620e8c4f1d1407c9234be00a392b54ca804324e59b49a9e6e204eb8d26` |
| `bad-not-png.bin` | 不适用 | 纯文本 | 272 | `131fffbc25d75ae57417e6fe4d36d3e32fa7773a6f6ee1eee252a7a1f5f7646e` |

图案定义（见 `lab/make_png.py`，逐像素公式，无随机数）：

- **asset-a**：底蓝 `#145A70`；`|x-y| ≤ 1` 画白色对角带；右下 8x8 象限完全透明（alpha=0）。
- **asset-b**：底橙 `#E87E4F`；`|x+y-15| ≤ 1` 画青色 `#32A5A0` 反对角带；左下半象限 alpha=128。

复现字节的方法：

```sh
python3 -I training/lab/make_png.py /tmp/regen
sha256sum training/assets/asset-a.png /tmp/regen/asset-a.png   # 两个摘要必须相同
```

## 4. 渲染结果基准（三份必须完全相同）

| 输出 | 尺寸 | 字节数 | sha256 |
|---|---|---|---|
| `02-baseline-render.png`（退役前，实例 A） | 320x240 | 6397 | `3583e97c31e961ae2fdceba69ac941fac9d172efb8baea1b0c909e598ae23bcf` |
| `04-render-after-retire.png`（退役后，同快照） | 320x240 | 6397 | 同上 |
| `05-render-instance-b.png`（实例 B 导入后） | 320x240 | 6397 | 同上 |

服务自带像素比较接口的结果（`04-refreeze-fail-compare-baseline-vs-after-retire.json`）：

```json
{"width": 320, "height": 240, "changedPixels": 0, "maxDelta": 0, "meanDelta": 0}
```

`changedPixels=0` 与三份文件 sha256 相同互为印证：一条来自服务的解码像素比较，
一条来自文件字节比较。

## 5. 哪些值会变（不要把它们写进核对基准）

| 字段 | 为什么变 | 影响核对吗 |
|---|---|---|
| `createdAt` / `updatedAt` / 事件 `at` | 墙上时钟 | 不影响，核对时忽略 |
| 交换包外层 `package.digest` | `CanonicalDigest(snapshot)` 覆盖含 `createdAt` 的完整快照结构 | 不影响内容核对；素材摘要与 `snapshot.digest` 不变 |
| `evidence/run/` 端口号 | 每次绑定空闲端口 | 不影响 |
| 冲突包重封口摘要 `93b535b8…` | 由固定篡改内容算出，内容固定则稳定，但它只是教学道具 | 不作产品基准 |

## 6. 一键核对

```sh
python3 -I training/lab/verify_evidence.py

```

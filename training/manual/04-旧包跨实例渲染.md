# 04 旧包跨实例渲染

对应实验脚本第 5 段，证据前缀 `05-cross-instance-*`。

## 一、两个实例是真正独立的

实验启动两个 atlas 进程，各自独占自己的状态文件，互不共享磁盘：

| 实例 | 状态文件 | 导入前 `/v1/status` |
|---|---|---|
| 实例 A | `evidence/run/instance-a/state-a.json` | 含退役素材、撤回快照、2 个成功任务 |
| 实例 B | `evidence/run/instance-b/state-b.json` | `sceneCount=0, assetCount=0, snapshotCount=0`（全零，见 `instance-b-status-before.json`） |

这模拟的真实场景：把旧生产实例的场景包交给一个新实例（灾备演练、环境迁移、合作方交接）。

## 二、导出：交换包里有什么

```sh
GET /v1/snapshots/snap-00000003/package
```

得到 `atlas-scene` v1 包（完整内容存于 `05-exported-package.json`），结构：

```
package
├── format/version      格式标识，导入首先验
├── digest              外层封口摘要（CanonicalDigest(snapshot)）
└── snapshot
    ├── document        冻结时的完整场景文档
    ├── digest          快照摘要（只覆盖 document + assets）
    ├── state           导出时快照状态（本实验为 revoked，仅作记录）
    └── assets          素材闭包，含完整 PNG 字节
```

来源可追溯（`05-cross-instance-package-embedded-png-vs-source.json`）：

```json
{
  "sourceSha256": "fce5d44a…3c2d",
  "packageEmbeddedSha256": "fce5d44a…3c2d",
  "byteIdentical": true
}
```

包内素材与 `training/assets/asset-a.png` **逐字节相同**。一个包就是一份自包含的历史，
不依赖源实例的素材服务。

## 三、干净实例导入：成功路径

```sh
POST /v1/imports/emblem-copy   {"name":"跨实例恢复的印记","package":{……}}
→ 201
```

证据 `import-on-clean-instance-201.json`：

```json
{"id":"emblem-copy","revision":1,"state":"active","documentEqual":true}
```

导入语义（与 `internal/service/packages.go` 行为一致）：

1. 先验外层摘要、快照摘要、素材闭包、素材摘要和尺寸，任何不符整笔失败；
2. 包内素材在目标实例不存在 → 以 **available** 状态落地（退役是源实例的本地状态，不随包传播为事实）；
3. 产生一个**全新的 active 场景，revision 从 1 重新计数**；源快照不会作为目标实例的快照记录落地。

之后在实例 B 上正常冻结、渲染：

| 步骤 | 结果 | 证据 |
|---|---|---|
| 冻结 `emblem-copy` revision 1 | 新快照，摘要 `f4802cc4…86de`，与实例 A 快照摘要**相同** | `freeze-on-instance-b.json` |
| 渲染任务 | `job-00000005` → `png-00000007`（序号在独立状态盘上重新开始） | `render-on-instance-b.json` |
| 输出 PNG | 320x240 / 6397 字节 / sha256 `3583e97c…23bcf`，与实例 A 基准**字节级相同** | `05-render-instance-b.png` |

**相同的固定输入（文档+素材字节）决定相同的快照摘要和相同的渲染像素**，与运行在哪个实例无关。

## 四、三条失败路径：导入是整笔事务

### 4.1 外层摘要被破坏 → 400

把包的 `digest` 改成全 0，其余不动：

```json
{"code":"invalid","error":"package checksum mismatch"}
```

证据 `tampered-package-checksum-400.json`。校验在解析任何业务内容之前就失败。

### 4.2 同名异内容 → 409（需要先合法重封口）

为了让请求越过摘要校验、到达业务冲突层，实验：

1. 在实例 B 预置 `asset-b`（橙底，摘要 `798c4762…8d26`）；
2. 把包内素材键改为 `asset-b`、记录内 `id` 同步改写、文档引用同步改写，
   但携带的仍是 asset-a 的蓝底字节；
3. 用培训辅助工具 `lab/digesttool`（直接调用项目自身的
   `model.SnapshotDigest` / `CanonicalDigest`）重算两层摘要；
4. 重新提交 → **409 `destination asset conflicts with package`**。

证据：`same-id-different-content-import-409.json`、重封口摘要
`repackaged-conflict-digest.json`（`93b535b8…`）。

随后 GET 目标场景返回 404（`conflict-scene-not-created-404.json`）：
**整笔事务回滚，场景没有半落地。**

### 4.3 同名素材在目标实例已退役 → 409

把实例 B 的 `asset-b` 退役后用同一个合法封口的包再导入：

```json
{"code":"conflict","error":"destination asset conflicts with package"}
```

证据 `retired-asset-import-409.json`。共享素材必须"内容相同 **且** 仍 available"，
两个条件缺一即整笔拒绝。

## 五、校验顺序总览（导入单个事务内）

```
格式 format/version
  └─> 外层 package.digest
        └─> 快照结构与 snapshot.digest（文档 + 闭包）
              └─> 闭包完整性：引用数 = 素材数、键名=记录 id、素材摘要、PNG 尺寸
                    └─> 目标场景 ID 未占用
                          └─> 每个共享素材：同摘要 且 available，否则整笔 409
```

任一环节失败都不会写入任何场景或素材记录。

## 六、跨实例结果的最终核对

```
实例 A 基准 png-00000007  sha256 3583e97c…23bcf
实例 B 输出 png-00000007  sha256 3583e97c…23bcf   ← 字节级相同
两实例快照摘要            f4802cc4…86de          ← 相同
包内嵌素材 vs 源文件       byteIdentical=true
```

配合 `evidence/contact-sheet.png` 底部两行绿色 `CHANGED=0`，
可同时从"摘要、像素、图像"三个层次向学员证明跨实例一致性。
